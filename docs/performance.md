# Performance and memory

Shelf is a local desktop indexer, so performance work starts with the filesystem
and SQLite before the UI.

## Current choices

- Virtualized grid and list views keep only visible rows in the DOM.
- Thumbnails are bounded to 128/256/512/1024 px buckets and generated by a
  2–4 worker pool.
- Native app icons are queued with a concurrency limit of 2, cached at most 96
  entries, and capped at 512 KiB each.
- Text snippets are cached at most 120 entries.
- Quick Look rejects original images above 64 MiB rather than loading them into
  the WebView.
- Duplicate detection narrows by size, shares one 1 MiB read buffer across
  hashes, and hashes only same-size candidates.
- Scan writes SQLite in batches of 512 and uses WAL with a separate reader
  connection.
- Search is debounced at 120 ms and stale responses are discarded.
- The cleanup reclaimable count is cached for 30 seconds.
- App directories add only `.desktop`/AppImage declarations, not entire system
  trees.

## Measuring

Run the app with a scratch DB, then measure the whole WebKit process tree:

```sh
ps -eo pid,ppid,rss,comm | grep -E 'shelf-app|WebKit'
```

Useful checks:

```sh
# Rust allocation profile for a scan or duplicate pass
cargo run --release -p shelf-cli -- index ~/Downloads

# Time an indexed query
time cargo run --release -p shelf-cli -- query "pdf last week"

# Database size after a scan
du -h "$HOME/.local/share/shelf/index.db"
```

Record the machine, kernel, filesystem, file count and whether previews were
generated. Do not compare cold and warm scans without saying which one ran.

## Review targets

These are review targets, not measured promises:

- Idle RSS: no unbounded growth after scrolling thousands of rows.
- No unbounded queues for thumbnail or icon requests.
- No full-file read on the UI thread.
- Indexing memory stays proportional to one batch plus SQLite, not the tree.
- Scrolling does not generate thumbnails for off-screen rows.

## Known costs

- The WebKit process dominates idle memory.
- SHA-256 duplicate passes read candidate files end-to-end.
- `du` measures system cache sizes for cleanup.
- Full-disk scans are I/O-bound; watcher events are coalesced.
- FTS5 trigram indexes increase database size and write cost.
